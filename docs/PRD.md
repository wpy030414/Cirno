# PRD — Cirno

## 产品目标

- 做一个 **Windows 原生的 Agent 座舱**：一个窗口里同时驱动多个 Claude Code / Codex 会话，状态一直下沉到任务栏。
- 「原生」不是装饰词：界面用 WinUI 3 / Fluent 2 / Mica 自己画，而不是给终端或 Electron 套壳。
- 主题是可选增强，不是默认姿态：默认零图片、纯正 Fluent；想要氛围就切「大肥鱼」。

## 用户与使用场景

- **目标用户**：项目作者本人（单人使用，无需账号体系、无需多语言、无需 GUI 安装向导以外的分发力）。
- **典型场景**
  - 三个仓库并行推进：一个会话在改代码、一个在跑测试、一个在等审批——侧边栏一眼看清谁在跑、谁卡住。
  - 同一份工作用两个后端对照：Claude 会话负责重构，Codex 会话负责审查，各自绑定不同的 provider 与模型。
  - 最小化到托盘后继续工作：任务栏图标变成「待确认」，点一下就跳到那张审批卡。

## 核心问题

1. **终端无法承载多会话**：一屏一个 TUI，切来切去靠记忆；状态、历史、审批都散落在不同 tab 里。
2. **Electron 壳既重又改不动**：想给现成 Agent 换个界面，只能打补丁；上游一升级就失效，能做的最多是把别人的界面染个色。
3. **会话级模型/supplier 不可见**：真实跑的是哪个模型、走的哪个端点，界面里常常看不出来。
4. **系统层完全缺席**：后台跑着的会话在任务栏上没有任何存在感，用户只能靠切窗口确认。

## 功能及其意义

| 功能 | 解决什么 | 为什么需要 |
|---|---|---|
| 侧边栏多会话管理 | 多任务并行时无法掌控全局 | 按项目分组 + 状态点 + 未读 + 搜索，让「哪个会话在等我」变成零成本判断 |
| 会话级 provider / model | 模型与端点的选择被藏起来 | 每个会话独立绑定 provider、模型、权限模式，界面如实显示「配置值 / 实际生效值」 |
| 原生 GUI 体验 | 终端与 Electron 的表达力不足 | 虚拟化时间线、原生 diff、可编辑的审批卡、全键盘操作——这些是套壳做不到的 |
| 自定义主题 | 长时间使用需要视觉舒适与个性 | 默认纯 Fluent；可选「大肥鱼」插画主题，配色由插画取色生成，明暗/高对比度完整 |
| 系统级会话状态 | 后台任务在系统层不可见 | 任务栏进度态、叠加徽标、缩略图工具栏、托盘、跳转列表——不切窗口也能感知与操作 |

## 功能之间的关系

- **多会话是主轴**：provider/model 是会话属性，系统状态是会话状态的聚合投影，主题是全局外观。
- **系统状态依赖会话状态机**：只有会话有明确状态（空闲/运行/待审批/失败），任务栏与托盘才有东西可显示。
- **主题与会话解耦**：换主题不影响任何会话；主题只改资源字典与装饰层。
- **后端能力差异被吸收在会话层**：界面永远面对同一套「会话—轮次—条目—审批」，不因后端不同而分叉。

## 范围与非目标

**范围内**

- Windows 11 桌面端单机应用；Claude Code 与 Codex 两种后端。
- 多会话并发、会话恢复与分叉、会话级 provider/model/权限模式。
- 原生渲染：消息、思考、计划、命令输出、文件改动 diff、审批。
- 两套主题：内置默认（零图片）+「大肥鱼」。
- 任务栏 / 托盘 / 跳转列表的系统级状态呈现。
- MSI 分发，缺依赖时引导安装。

**范围外（明确不做）**

- 各后端的 skill / plugin / MCP 管理：后端自己的配置照常生效，Cirno 只透传、不呈现、不管理。
- 定时任务、资料库、云同步、账号体系、遥测、自动更新探测等常见 GUI Agent 增值云功能。
- 自研模型 API 客户端：一律通过后端官方协议驱动。
- 跨平台（macOS / Linux / 移动端 / Web）。
- 多窗口、标签页式布局（首版不做，侧边栏足够）。

## 成功指标

- 4 个会话（2 Claude + 2 Codex，不同 provider/model）并发运行，互不串流、互不阻塞。
- 关闭窗口后会话继续运行；重开后会话与时间线完整还原。
- 最小化状态下出现审批请求时，任务栏与托盘能明确提示，一键直达。
- 冷启动到可交互 < 1.5s；万条消息会话滚动不掉帧。
- 全程不依赖鼠标可完成：新建会话 → 提问 → 审批 → 查看 diff → 中断。
- 退出后无残留子进程；删除用户数据目录即完全干净。

## 里程碑

| 阶段 | 目标 | 出口条件 |
|---|---|---|
| M0 骨架 ✅ | WinUI 壳 + 主题管线打通 | 应用可启动、Mica 正常、明暗切换正确、主题由构建期生成且无数值硬编码 |
| M1 单会话 ✅ | Claude 后端 + 原生渲染 + 审批 | GUI 内完成一次带工具调用的真实任务，可允许/拒绝/中断 |
| M2 多会话 ✅ | 并发编排 + 持久化 + 侧边栏 | 重开应用完整还原；3 会话并发不串流 |
| M3 第二后端（暂缓） | Codex 后端 + provider/model 选择 | Claude 与 Codex 会话同窗并存，各自 provider/model 正确 |
| M4 系统状态 ✅ | 任务栏 / 托盘 / 跳转列表 | 后台审批可被任务栏明确提示并一键处理（跳转列表未做） |
| M5 打磨 ✅ | diff、计划、键盘全流程、性能 | diff 与键盘全流程达成；性能指标未做基准测试 |
| M6 分发 ← 下一步 | 主题收尾 + MSI + 依赖自举 | 干净 Windows 11 机器上用 MSI 装完即可运行 |
